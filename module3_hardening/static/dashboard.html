FIDO2 Origin-Binding Security Cryptographic Proof

Why Passkeys Cannot Be Phished:

In FIDO2/WebAuthn, the browser signs the genuine destination domain (rpId) into clientDataJSON.origin.

When an attacker's proxy (e.g. evil-login.net) forwards the signature to login.microsoftonline.com, the origin hashes do NOT match. The IdP rejects the login cryptographically!

Cryptographic Token Binding (RFC 9449 DPoP)

Proof of Possession: Even if a reverse proxy captures a session token, the token is cryptographically bound to the employee device's private key. Replaying the token from the attacker's machine triggers a token-binding failure.
